# Notes 与 Projects 第一阶段

## 目标

第一阶段先完成个人可用的记录闭环：创建项目、在项目内组织笔记、搜索与置顶、自动保存，并从笔记创建可双向返回的任务。编辑器使用 Plate 53；模板、标签和 AI 提取留在后续迭代。

## 核心对象

- `Project`：跨邮件、日历、任务和笔记共享的上下文对象，包含名称、领域、说明、颜色和归档状态。
- `Note`：属于零个或一个项目，包含标题、正文、类型和置顶状态。
- `EntityLink`：通用关系仓库与 API 已建立，承接项目成员、邮件任务来源、任务排期、会议笔记、准备任务和跟进任务关系。任务与笔记会自动镜像项目归属，邮件与日程可在详情中直接选择项目。
- `TaskSourceReference`：现阶段继续承担任务来源；笔记创建任务时保存 `/notes?note=<id>` 返回链接。

## 界面

Notes 使用扁平的两栏布局：

1. 顶部横向空间栏显示全部、置顶、未归档和项目筛选；
2. 左栏负责搜索、创建和选择笔记；
3. 右栏是无边框块编辑器、项目/类型/置顶控制和关联任务区。

Notes 页面不保留常驻 AI 侧栏，避免出现应用导航、项目、列表、编辑器和 AI 五重层级。正文默认 16px，编辑区优先获得剩余宽度。

标题或正文变更后立即更新本地界面，并在停止输入 700 ms 后写入数据库。切换笔记或创建关联任务前会先刷新待保存内容。

## 编辑器和存储格式

Notes 直接使用 Plate 53 和项目内的 shadcn/Radix 组件。当前包含：

- 基础块、列表、待办、引用、代码块、表格、分栏、折叠块和数学公式；
- 固定工具栏、浮动工具栏、`/` 内容块菜单、拖拽和右键块菜单；
- Markdown/DOCX 导入导出、自动格式化和深色模式；
- 评论、建议、AI 和外部上传相关入口保持禁用或不接入，直到对应后端能力完成。

正文以 `plate-json-v1:` 前缀加 Plate JSON 存入现有 `notes.content` 字段。普通纯文本仍可直接打开并在首次编辑后保存为结构化格式。列表摘要、全文筛选和“转为任务”通过统一文本投影读取正文，避免暴露 JSON；表格按行列投影，仍可被搜索和任务摘要读取。

## 编辑器验收

Plate 已直接接入正式 `/notes` 页面，原实验页已停用并跳转到正式 Notes，旧编辑器实现已移除。编辑器继续使用现有 Notes 自动保存、项目筛选、搜索和任务关联数据流。

仍需持续验收中文输入法、长文、复杂粘贴、撤销/重做、移动端和键盘操作。Plate 官方编辑器模板作为组件基线保留，但 AI API 路由、浏览器端密钥设置、Copilot 和 AI 触发入口均未启用；外部文件上传也尚未配置。

后续验收重点：

1. 中文输入法、长文、粘贴、撤销、移动端和键盘操作稳定；
2. 自动保存、关联任务、项目筛选、纯文本导入和搜索能力无回退；
3. 根据真实使用情况裁剪未使用插件，控制前端包体和维护成本；
4. 图片与文件上传必须在持久化后端接入后再开放。

## 当前关系闭环

`Note → 创建 Task → TaskSourceReference(note) → /notes?note=<id>`

笔记通过来源表反查关联任务，并提供 `/tasks?task=<id>` 精确入口。删除笔记只解除来源引用，不删除已经创建的任务。

## 后续顺序

1. 完成 Plate 在正式 Notes 页的中文输入、长文、粘贴、移动端和键盘操作人工验收；
2. 完善会议笔记模板；事件已经可以创建并双向打开会议笔记；
3. 标签和数据库级全文检索；
4. GPT 总结、改写和行动项提取，并保留人工确认；
5. 根据实际需要接入持久化图片和文件上传。
