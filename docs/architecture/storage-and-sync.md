# 本地存储与首次邮件同步

## 当前实现

个人版先使用 PGlite 作为嵌入式 PostgreSQL。数据保存在项目根目录的 `.data/postgres`，表结构保持 PostgreSQL 兼容，以便在线版迁移到托管 PostgreSQL。

核心数据表：

- `accounts`：邮箱账户、显示名称、颜色、同步范围和健康状态；
- `encrypted_credentials`：加密后的 IMAP/SMTP 配置；
- `mail_folders`：远端文件夹及 UIDVALIDITY；
- `mail_threads`、`mail_messages`：统一收件箱的本地摘要索引；
- `sync_cursors`：最新 UID、历史回填位置和首次同步状态；
- `sync_runs`：每次同步的状态、计数与错误。

## 凭据安全

邮箱密码不会以明文写入数据库或日志。服务端使用 AES-256-GCM，每条凭据使用随机 IV，并以账户 ID 作为附加认证数据。开发版会在首次保存账户时自动生成 `.data/master.key`；部署版应使用环境变量 `KALENDER_MASTER_KEY` 注入密钥。

数据库与主密钥必须分开备份和控制访问。未来正式在线部署需要增加密钥版本、轮换和重新加密流程。

## 保存与同步流程

1. 用户先点击“测试连接”；
2. 服务端校验邮箱地址、端口和服务器地址，并拒绝本地/私有网络目标；
3. 分别验证 IMAP 登录和 SMTP 身份，但不发送邮件；
4. 点击“保存并开始同步”后再次验证，防止保存过期或被修改的配置；
5. 加密凭据并幂等保存账户；
6. 读取远端文件夹，优先同步 Inbox、Sent、Drafts、Archive；
7. 首次请求最多保存 100 封摘要，同时记录 UID 和历史回填位置；
8. 完成后跳转统一收件箱。

## 账户管理

设置页从 `accounts` 表读取真实账户列表，并显示同步健康状态、同步范围与 `last_sync_at`。每个账户支持：

- 立即同步：读取最新一批摘要并刷新最后同步时间；
- 暂停/启用：暂停时保留本地邮件，但禁止手动同步；
- 重新配置：只把非敏感服务器参数返回浏览器，密码字段始终为空；
- 删除：用户确认后级联删除凭据、邮件索引、同步游标和运行日志。

## 后台增量同步

首次访问账户或收件箱接口后，本机服务启动单例后台调度器，默认每 3 分钟检查一次启用账户：

- 使用文件夹 `UIDVALIDITY + last_uid` 只查找新增 UID；
- 使用 `backfill_before_uid` 每次最多回填 100 封历史摘要；
- 每个文件夹补偿扫描最近 200 个 UID，校正 `\\Seen` 和 `\\Flagged`；
- 对补偿窗口中远端已不存在的 UID 删除本地索引，从而反映移动或删除；
- UIDVALIDITY 变化时清理该文件夹旧索引并重新建立游标；
- 每个账户使用进程内并发锁，避免手动同步和后台同步重叠；
- 失败账户采用指数退避，最长等待 1 小时后重试；
- 页面每 10 秒刷新账户状态和最后同步时间；
- 应用重启后从数据库游标继续，不重新读取已经完成的历史批次。

该调度器适用于当前本机单进程版本。未来在线多实例部署需要外部任务队列、分布式锁和独立同步 Worker。

## 邮件正文按需读取

同步阶段只保存邮件头、摘要索引和附件元数据。用户打开一封邮件时，服务端才根据本地保存的账户、文件夹和 IMAP UID 读取原始邮件：

- 单封原始邮件限制为 25 MB，避免异常邮件占用过多内存；
- 使用 `postal-mime` 解析 MIME，分别得到纯文本和 HTML 正文；
- HTML 通过严格白名单清洗，移除脚本、表单、事件属性、危险 CSS 和危险 URL，同时保留颜色、字号、间距和表格等安全排版；
- CID 内嵌图片在大小和类型限制内转换为本地数据图片；远程图片保留为阻止状态，只有用户点击“显示图片”后才由浏览器加载；
- 安全链接只允许 `http`、`https` 和 `mailto`，并强制在新窗口隔离打开；
- 清洗后的正文、纯文本和摘要写入 `mail_messages`，以 `body_loaded_at` 和 `body_cache_version` 标记缓存完成；清洗策略升级时旧缓存会自动重新读取；
- 同一正文的并发请求会合并；再次打开直接使用本地缓存，不重复访问 IMAP；
- 密码和原始 MIME 不会返回浏览器；只有受限制的 CID 图片内容可作为已清洗正文的一部分返回。

## 当前限制与下一步

- 正文已支持按需读取、安全缓存和用户主动“重新从服务器读取”；自动缓存清理策略仍待实现；
- 右键菜单的已读、星标和归档操作会先写入远端 IMAP，成功后更新本地状态；归档目标必须是服务器明确的 Archive 文件夹；
- 已接入新增邮件、历史回填和最近 200 个 UID 的状态补偿；更早邮件的状态变化需要后续周期性深度审计；
- 已实现标记已读/未读、星标、归档、删除、移动、文件夹管理、附件下载、邮件发送和草稿附件；
- PGlite 适合当前本机单用户版本，在线多实例版本应切换到托管 PostgreSQL。
