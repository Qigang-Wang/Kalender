# 上下文右键菜单规划

## 1. 目标

右键菜单用于缩短高频对象操作路径，但不能成为功能的唯一入口。邮件、任务、日程、笔记等对象应复用同一套命令定义，使右键菜单、三点菜单、快捷键和命令栏执行完全相同的业务动作。

设计目标：

- 常用对象操作在一次右键后即可找到；
- 根据对象状态、账户能力和当前权限动态显示或禁用命令；
- 外部写入、删除和发送等高风险操作继续遵守确认与撤销规则；
- 不破坏浏览器和操作系统的复制、粘贴、拼写检查及文本选择能力；
- Web 与桌面端使用一致的命令名称、分组和结果反馈。

## 2. 使用判断

### 应使用自定义右键菜单

- 邮件、任务、笔记等高密度列表行；
- 日历事件、任务时间块及空白时间段；
- 账户、日历源、任务清单等可管理对象；
- 附件、相关内容卡片和 AI 操作记录；
- 用户已经明确指向一个对象，并且存在至少两个有价值的快捷操作。

### 应保留系统菜单

- 邮件正文和普通可选择文本；
- 输入框、搜索框、富文本编辑器和代码块；
- 页面空白区域及一级导航；
- 浏览器链接的普通打开、复制链接场景；
- 没有对象语义或只有一个操作的区域。

富文本编辑器内部不替换系统右键菜单。格式化、转任务和 AI 改写使用选中文本工具条或显式三点菜单，以保留复制、粘贴和拼写检查。

## 3. 页面与对象菜单矩阵

| 位置与对象 | 第一组：直接操作 | 第二组：组织与关联 | 危险操作 | 阶段 |
|---|---|---|---|---|
| Inbox 邮件行 | 打开、标记已读/未读、添加/取消星标、回复、转发 | 创建任务、AI 总结、移动到文件夹 | 归档、删除 | P2；基础版已完成 |

| 日历事件 | 打开、编辑、加入会议、复制 | 创建会议笔记、创建跟进任务、移动到其他日历 | 取消/删除事件 | P3 |
| 日历空白时间段 | 新建事件、安排任务、创建专注时段 | 粘贴时间范围 | 无 | P3 |

| 任务行 | 完成/恢复、打开、快速改截止时间、修改优先级 | 安排到日历、关联邮件/事件/笔记、复制任务 | 删除任务 | P3 |
| 任务清单/项目 | 打开、重命名、修改颜色 | 排序、移动任务、设为默认清单 | 归档/删除清单 | P3 |
| 笔记列表行 | 打开、置顶/取消置顶、重命名、复制 | 创建任务、关联事件、移动笔记本、导出 | 删除笔记 | P3 |
| Today 中的邮件/任务/事件卡片 | 复用来源对象的直接操作 | 打开来源、查看相关内容 | 复用来源对象的危险操作 | P3 |
| 相关内容卡片/实体链接 | 打开来源、复制对象链接 | 更改关联、添加其他关联 | 解除关联 | P3 |
| AI 建议卡片 | 接受、修改、复制、重新生成 | 查看数据来源、保存为笔记、创建任务 | 忽略建议、撤销已执行操作 | P4 |
| AI 工具执行记录 | 查看参数和结果、重试 | 打开受影响对象 | 撤销（仅支持时显示） | P4 |

## 4. 不应加入菜单的位置

- 一级导航只负责切换模块，设置放在明确的账户或模块入口；
- 页面标题和装饰卡片不提供右键菜单；
- 邮件正文、笔记编辑器和所有表单控件保留系统菜单；
- 手机端不依赖长按发现功能，使用可见的三点菜单；
- 同一个操作如果没有明确对象目标，不放入上下文菜单。

## 5. 菜单结构规范

每个菜单建议不超过 7–9 个可见命令，并按以下顺序分组：

1. 打开、编辑、回复等主要动作；
2. 状态切换，例如已读、星标、完成、置顶；
3. 创建关联、移动和 AI 辅助操作；
4. 归档、断开和删除等危险操作。

具体要求：

- 标签根据状态变化，例如“标记为未读”“取消星标”“恢复任务”；
- 不可用命令必须给出原因，例如“需配置 GPT”“账户已暂停”；
- 危险命令放在最后一组并使用克制的危险色；
- 禁止超过一级子菜单；文件夹很多时改用可搜索选择器；
- 执行中显示进度并禁止重复点击；
- 成功后显示简短结果，支持撤销的操作同时显示“撤销”；
- 菜单随指针出现并限制在可视区域内，滚动、缩放或切换页面时关闭。

## 6. 多选规则

- 右键对象已在多选集合中时，菜单作用于整个选中集合；
- 右键未选中的对象时，先取消原多选，只作用于当前对象；
- 批量菜单只显示所有选中对象共同支持的命令；
- 跨账户批量操作必须按账户拆分执行并分别报告结果；
- 批量删除、移动和外部写入必须显示对象数量与账户范围。

## 7. 键盘、触屏与系统菜单

- 支持鼠标右键、键盘菜单键和 `Shift + F10`；
- 使用方向键、Home/End 移动焦点，Enter/Space 执行，Esc 关闭；
- 关闭后把焦点还给原对象；
- 菜单使用 `role="menu"` 和 `role="menuitem"`，禁用原因可被辅助技术读取；
- 提供 `Shift + 右键` 打开浏览器原生菜单的保底路径；
- 手机和平板使用三点菜单；长按仅作为可选增强，不能干扰文本选择和拖拽；
- 菜单项仍需在工具栏、详情页或三点菜单中提供可发现入口。

## 8. 安全与数据一致性

- 已读、星标、归档等远端操作先提交 Provider，成功后更新本地索引；
- 可安全回滚的动作可以乐观更新，但失败时必须恢复原状态；
- 发送邮件、删除数据、取消会议、断开账户始终需要确认；
- 确认界面显示目标账户、对象名称、影响范围和不可逆后果；
- AI 可以建议菜单动作，但不能绕过相同的确认和权限检查；
- 操作使用稳定幂等键，避免网络重试导致重复发送或重复创建；
- 一个账户失败不能阻止其他账户的批量操作，并应分别显示结果；
- 日志只记录动作类型、对象 ID、结果和耗时，不记录正文或凭据。

## 9. 技术设计

建立共享的命令注册表，避免每个页面独立实现菜单逻辑。

建议核心类型：

```ts
type ContextTarget =
  | { kind: "mail-message"; id: string; accountId: string }
  | { kind: "mail-account"; id: string }
  | { kind: "attachment"; id: string; messageId: string }
  | { kind: "calendar-event"; id: string; calendarId: string }
  | { kind: "calendar-slot"; startsAt: string; endsAt: string }
  | { kind: "task"; id: string }
  | { kind: "note"; id: string }
  | { kind: "entity-link"; id: string }
  | { kind: "ai-operation"; id: string };

interface ContextCommand {
  id: string;
  label: string;
  group: "primary" | "state" | "organize" | "danger";
  risk: "read" | "local-write" | "external-write" | "destructive";
  visible(target: ContextTarget): boolean;
  enabled(target: ContextTarget): { ok: boolean; reason?: string };
  execute(target: ContextTarget): Promise<void>;
}
```

同一个 `ContextCommand` 应供以下入口复用：

- 右键菜单；
- 列表行三点菜单；
- 详情页工具栏；
- 全局命令栏；
- 键盘快捷键；
- 桌面端系统菜单。

## 11. 验收标准

- 用户右键任一支持对象时，150 ms 内显示正确菜单；
- 菜单不超出视口，关闭后焦点返回原对象；
- 仅使用键盘可以打开、浏览、执行和关闭菜单；
- 所有右键命令都有可见的非右键入口；
- 文本编辑、复制粘贴和拼写检查不受影响；
- 禁用命令说明原因，不出现“点击后无反应”；
- 远端写入失败时本地状态不会错误显示为成功；
- 危险操作不会绕过确认，支持撤销的操作提供撤销入口；
- 多账户批量操作能够分别报告成功和失败；
- 自动化测试不会在未明确授权时修改真实邮箱、日历、任务或笔记。
