# UI 风格与交互规范

## 设计基线文件

- 交互稿：[`mockups/personal-ai-workspace-ui.html`](mockups/personal-ai-workspace-ui.html)
- 静态预览：[`mockups/personal-ai-workspace-ui.png`](mockups/personal-ai-workspace-ui.png)
- 分页面基线：[`mockups/screenshots/`](mockups/screenshots/)

这两个文件是当前 UI 视觉基线。后续实现应用 Shell、Today、Inbox、Calendar、Tasks、Notes 和 AI Command 时，应优先保持其布局层级、信息密度、色彩克制和 AI 操作确认方式；需要偏离时，应同步更新本规范和基线文件。

## 1. 设计方向：Quiet Intelligence

中文定义：**安静、清晰、随时可调用的智能。**

界面参考 Notion 的内容清晰度、TickTick 的时间感和 Outlook 的信息效率，但不复制任何一款产品。AI 不占据整个产品，也不使用持续闪烁或大面积渐变；它应像一个始终在场、但不打断工作的助手。

核心感受：

- 安静而不冷淡；
- 专业但不是企业后台；
- 信息密度适中；
- 内容优先，装饰克制；
- AI 能力可见，但不喧宾夺主；
- 多账户来源清楚且不会造成视觉噪声。

## 2. 信息架构

一级导航固定为：

1. Today
2. Inbox
3. Calendar
4. Tasks
5. Notes
6. AI Command

侧栏底部放置账户、同步状态和设置。全局顶部保留一个命令入口，用于搜索、快速记录和 AI 指令。

### 桌面布局

- 左侧导航：200–224 px；
- 主内容区：自适应；
- 右侧上下文面板：280–340 px，可折叠；
- 主内容根据模块切换单栏、双栏或三栏；
- 右侧面板统一承载相关内容、AI 建议和操作预览。

### 典型模块布局

- Today：主时间线 + 右侧 AI 每日简报；
- Inbox：邮件列表 + 邮件正文 + 相关内容/AI；
- Calendar：周视图 + 可折叠任务池；
- Tasks：列表/Today + 任务详情；
- Notes：笔记列表 + 编辑器 + 相关内容；
- AI Command：对话区 + 可审查的工具操作记录。

## 3. 视觉系统

### 色彩

主色采用低饱和靛蓝，用于当前导航、主操作、焦点和时间块：

- Light primary：`#5668E8`
- Dark primary：`#7C8CFF`
- Light canvas：`#F7F8FA`
- Light surface：`#FFFFFF`
- Light text：`#20232A`
- Light muted text：`#6F7580`
- Light border：`#E5E7EB`
- Dark canvas：`#111318`
- Dark surface：`#181B22`
- Dark text：`#F1F3F5`
- Dark muted text：`#A0A6B0`
- Dark border：`#2A2E37`

状态色只表达真实状态：

- 成功/完成：绿色；
- 临近截止/待确认：琥珀色；
- 错误/逾期/危险操作：红色；
- AI 建议：主色的浅色背景，不单独使用炫彩渐变。

每个邮箱账户分配一个稳定颜色。颜色必须同时配合账户名称或图标，不能仅依赖颜色识别。

### 字体

- UI：`Inter Variable`, `Noto Sans SC`, system-ui；
- 邮件和笔记正文：同一字体栈，避免产品内出现多个视觉人格；
- 基础字号：14 px；
- 正文：14–15 px；
- 辅助文字：12–13 px；
- 页面标题：20–24 px；
- 只使用 400、500、600 三档字重。

### 间距与形状

- 以 4 px 为最小单位，主要使用 8、12、16、24、32；
- 输入框、按钮和列表行圆角：8 px；
- 弹层和重要卡片圆角：12 px；
- 避免每块内容都放进卡片；
- 分区优先使用留白和细分隔线；
- 阴影仅用于浮层、菜单和拖拽状态。

### 图标

- 使用 Lucide 风格线性图标；
- 常规尺寸 16–18 px；
- 导航图标必须配文字；
- 图标不承担唯一语义；
- 不为每个列表项添加无意义图标。

## 4. 核心组件

### 全局命令栏

- 支持搜索邮件、事件、任务和笔记；
- 支持自然语言 AI 指令；
- 支持快速创建；
- 明确区分“搜索结果”和“将执行的动作”；
- 快捷键为 `Ctrl/Cmd + K`。

### 列表行

- 默认安静，悬停时显示次要操作；
- 来源账户使用小色点加名称；
- 未读通过字重和标记共同表达；
- 列表中不堆叠多个彩色标签；
- 时间、状态和来源保持稳定位置。

### 上下文右键菜单

- 只用于具有明确对象语义的列表行、日程块、任务、笔记和关联卡片；
- 输入框、邮件正文、笔记编辑器、普通文本和页面空白保留系统菜单；
- 所有右键命令同时提供三点菜单、工具栏或命令栏入口；
- 菜单项按主要操作、状态、组织/AI、危险操作分组，危险操作位于底部；
- 动态标签反映当前状态，不可用项必须显示原因；
- 完整对象矩阵、键盘规则和实施阶段见 [`context-menu-plan.md`](context-menu-plan.md)。

### AI 建议

- 使用柔和主色背景或左侧强调线；
- 标明使用了哪些邮件、事件或笔记；
- 操作按钮使用具体动词，如“创建任务”“保存草稿”；
- 不使用模糊按钮，如“继续”“执行”；
- 用户可以修改 AI 生成内容后再确认。

### 外部写入预览

发送邮件、修改日程和删除数据时，显示：

- 将执行的动作；
- 目标账户；
- 具体字段变化；
- AI 使用的数据来源；
- 确认和取消按钮；
- 执行完成后的结果与撤销能力。

### 相关内容面板

右侧面板统一展示：

- 来源邮件；
- 相关任务；
- 关联日程；
- 会议或工作笔记；
- AI 建议；
- 操作历史。

## 5. 页面风格

### Today

- 顶部只显示日期、简短问候和快速记录；
- 主区是一条从早到晚的时间线；
- 未安排任务位于时间线旁，不与日程混在同一种视觉形态；
- 待回复邮件作为行动项出现，而不是显示完整收件箱；
- AI 每日简报控制在 3–5 条。

### Inbox

- 桌面使用三栏布局；
- 邮件列表强调发件人、主题、摘要和时间；
- 正文区保持阅读宽度，不铺满超宽屏幕；
- 账户来源始终可见；
- AI 总结位于正文上方的可折叠区域；
- 回复时明确显示发件账户。

### Calendar

- 日程颜色来自账户/日历；
- 任务时间块使用同一主色体系但形状不同；
- 当前时间线清晰但不过度醒目；
- 拖入任务时显示可落点；
- 日历右侧可打开任务池。

### Tasks

- 默认围绕 Today、Upcoming、Someday 组织；
- 优先级主要影响排序和细小标记，不整行染色；
- 详情中展示来源邮件和安排时间；
- 支持快速完成和撤销。

### Notes

- 使用“顶部空间筛选 + 笔记列表 + 编辑器”的扁平两栏结构；项目是邮件、日历、任务和笔记未来共享的业务对象，不只是文件夹；
- Notes 不显示常驻 AI 右栏，把横向空间优先留给阅读与写作；AI 仍通过全局命令栏进入；
- 笔记列表标题不小于 14px，摘要不小于 12px，编辑器正文默认 16px；
- 项目颜色只用于小圆点和来源提示，不大面积染色；
- 编辑器实时写入本地草稿并在 700 ms 停顿后自动保存，工具栏持续显示保存状态；
- 编辑器尽可能无边框；
- 工具栏按需出现；
- 会议笔记具有清晰的参会者、事件和行动项区域；
- 笔记中的任务可以提升为正式任务并保留原文链接。

### AI Command

- 不是普通聊天软件外观；
- 回答内容与工具执行记录分开；
- 工具调用显示为紧凑步骤；
- 对话中出现的邮件、任务、事件和笔记使用统一实体引用组件；
- 高风险操作始终进入确认面板。

## 6. 动效

- 常规过渡 120–180 ms；
- 仅用于状态变化、面板展开、拖拽和列表重排；
- 不使用循环动画；
- AI 生成时使用稳定的进度文字，不使用夸张粒子效果；
- 遵循系统“减少动态效果”设置。

## 7. 响应式与可访问性

- MVP 优先支持 1024 px 以上桌面布局；
- 768–1023 px 自动收起右侧上下文面板；
- 更窄宽度使用单栏和抽屉导航；
- 手机原生体验不属于首版目标，但 Web 页面不能完全不可用；
- 所有操作可通过键盘完成；
- 保留可见焦点状态；
- 文本和交互元素满足 WCAG AA 对比度；
- 状态不只通过颜色表达；
- 图标按钮提供可访问名称。

## 8. 首批设计交付

1. UI Token 和主题文件；
2. 应用 Shell；
3. Today 页面；
4. Inbox 三栏页面；
5. 邮件正文和回复编辑器；
6. AI 建议组件；
7. 外部写入确认面板；
8. Calendar 周视图；
9. Task 列表与详情；
10. Note 编辑器和相关内容面板。

## 9. 设计验收标准

- 用户可以在 5 秒内知道今天最重要的事情；
- 用户可以始终辨认当前邮件或事件来自哪个账户；
- AI 建议、草稿和已执行动作视觉上明确不同；
- 发送邮件前能清楚看到发件账户和收件人；
- 常用操作不超过两次点击或一次快捷键；
- 页面没有大面积无意义卡片和装饰；
- Light/Dark 两种主题都保持可读性；
- 仅使用键盘可以完成核心流程。
