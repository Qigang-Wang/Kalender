# 项目阶段路线图

- 适用范围：个人使用、多个邮箱账户、Web + 桌面端、GPT AI
- 计划基线：单人配合 Codex 开发
- 预计周期：剩余约 15–22 周，可用版本在第 8–12 周形成
- 开发策略：每个阶段都交付一条可实际使用的完整工作流
- 交互专项：右键菜单按 [`design/context-menu-plan.md`](design/context-menu-plan.md) 的对象矩阵和安全规则分阶段实施

## 总体阶段

| 阶段 | 目标 | 预计时间 | 主要交付物 |
|---|---|---:|---|
| P0 基础架构 | 建立稳定的多供应商边界 | 已完成 | MailProvider、注册表、统一路由、契约测试 |
| P1 账户与真实连接器 | 安全连接真实邮箱账户 | 2–3 周 | 数据库、OAuth、凭据存储、首个真实 Provider |
| P2 邮箱垂直链路 | 形成可持续使用的统一收件箱 | 3–4 周 | 增量同步、Inbox UI、线程阅读、发送与恢复 |
| P3 个人组织核心 | 连接任务、日历和笔记 | 3–4 周 | Today、Task、Calendar、Note、EntityLink |
| P4 AI 助手 | 让 AI 理解并操作四类数据 | 3–4 周 | AI Provider、AI Command、工具调用、每日简报、行动项工作流 |
| P5 桌面与本地体验 | 提供可靠桌面应用 | 2–3 周 | Tauri、通知、快捷键、有限缓存、自动更新 |
| P6 稳定化 | 达到长期个人使用标准 | 2–4 周 | 安全、备份、性能、异常恢复和连续使用验证 |
