## 1. P1：失效会话会取消用户数据过滤（已复现）

位置：[user-scope.ts](/home/messnix/QGW_Test/apps/web/src/server/user-scope.ts:3)、[proxy.ts](/home/messnix/QGW_Test/apps/web/src/proxy.ts:14)、[auth.ts](/home/messnix/QGW_Test/apps/web/src/server/auth.ts:671)。

代理只校验 Cookie 签名和有效期，不查询账户是否停用以及会话版本是否变化。数据库认证返回无用户后，`getUserScope()` 构造一个不启用用户过滤的范围；异常也被转换成相同状态。普通数据 API 没有再次强制要求有效用户。

隔离复现：管理员和普通用户分别登录；管理员创建仅自己可见的任务；确认普通用户最初看不到；管理员停用该用户后，该用户使用原 Cookie 请求 `/api/tasks`，返回 HTTP 200，包含管理员的任务。

应修复：Web 请求认证失败必须返回 401/403；后台任务通过明确的系统执行上下文访问全局数据。不能用“没有用户”隐式代表系统权限。增加停用、删号、密码重置、权限变更及认证异常的端到端隔离测试。

## 2. P1：网页笔记保存没有接入已有版本校验（已复现）

位置：[笔记 PATCH API](/home/messnix/QGW_Test/apps/web/src/app/api/notes/[noteId]/route.ts:17)、[笔记自动保存](/home/messnix/QGW_Test/apps/web/src/components/pages/notes-page.tsx:194)、[仓储版本条件](/home/messnix/QGW_Test/apps/web/src/server/note-repository.ts:332)。

仓储已经支持 `expectedUpdatedAt`，但网页 API 没传，前端也没发送。700 ms 防抖只能推迟尚未发送的请求，不能阻止在途请求交错；多标签编辑同样会互相覆盖。MCP 的版本测试通过并不覆盖这条网页路径。

隔离复现：读取初始版本，先保存新内容，再提交携带初始版本的旧内容；两次均返回 HTTP 200，最终存储内容变为旧内容。

应修复：复用现有版本比较，贯通 Web 请求与仓储；同一笔记保存串行化，只合并尚未发送的最新快照，冲突时保留本地编辑。任务、项目计划项网页 API 也应逐一接入其仓储已有的版本条件；邮件草稿保存另需补版本比较。

## 3. P2：离线操作的失败回执永久阻止有效重试（已复现）

位置：[calendar-operation.ts](/home/messnix/QGW_Test/apps/web/src/server/calendar-operation.ts:14)、[离线队列](/home/messnix/QGW_Test/apps/web/src/hooks/use-calendar-outbox.ts:70)。

操作成功和操作失败都持久化同一份回执。前端“重试”继续使用原操作 ID，因此只会读取旧错误，不会重新执行。

隔离复现：创建一个时间冲突，使带操作 ID 的新增请求返回 409；删除冲突事件；用原 ID 重试，仍返回 409，错误中甚至包含已经删除的冲突事件。

应修复：区分“确定未写入”“已写入”“结果不确定”。确定未写入的失败允许恢复执行或创建新的尝试；结果不确定时先核对远端，防止重复发送通知。前端根据状态提供相应操作，不能只有统一的重试按钮。

## 4. P2：Exchange 草稿创建缺少结果不确定时的防重机制（模拟复现）

位置：[exchange-draft-sync.ts](/home/messnix/QGW_Test/apps/web/src/server/exchange-draft-sync.ts:36)。

只有收到 CreateItem 响应后才保存远端草稿 ID。若服务器已创建，但响应丢失，本地没有关联；下一次自动保存或同步会再次创建。

模拟复现：第一次模拟服务器创建成功后客户端收到网络错误；第二次调用上传，CreateItem 总计执行两次，产生两个模拟远端草稿。

应修复：对首次创建保存持久化操作状态；可以用稳定的本地草稿标识关联远端并先查重，或先进入待核对状态。具体选择取决于 EWS 查询与扩展属性方案的验证结果。内存中的 Set 只控制并发，不解决响应丢失和进程重启。

## 5. P2：邮件和笔记搜索无法直接利用现有全文索引（已检查执行计划）

位置：[搜索 SQL](/home/messnix/QGW_Test/apps/web/src/server/workspace-search.ts:49)、[邮件全文索引](/home/messnix/QGW_Test/apps/web/src/server/database.ts:1321)。

邮件查询把邮件表、正文表等内容拼成一个 `to_tsvector`，而 GIN 索引分别建在两张表上，表达式也不同；笔记查询包含项目名，笔记索引没有该字段。此外，无索引支持的多个 `%关键词%` 条件通过 OR 连接。

隔离 EXPLAIN：邮件使用主键扫描再 Join/Filter，笔记使用项目排序索引再 Join/Filter；没有利用对应全文 GIN 索引。即使在诊断中关闭顺序扫描，也只是换成普通索引扫描后过滤。该结果说明索引与查询不匹配，不代表已经测得生产环境延迟。

应优化：按各表现有索引表达式分别取候选 ID 后合并，保留用户范围与分页；单独处理项目名和模糊匹配。先用有代表性的数据量测计划、耗时与缓冲区读取，再判断是否需要新增索引，不宜先增加缓存掩盖查询问题。
